Scrip

A payment rail that makes bridged XRP spendable by software. Agents pay per call in FXRP, priced in USD by Flare's FTSO, holding no gas token.

How a payment works

An agent requests a paid endpoint. The server answers 402 with a price in USD. The agent signs one offchain EIP-2612 permit. The facilitator submits it, moves FXRP, and the endpoint returns its result. The agent never sends a transaction and never needs C2FLR. 

agent --GET--> endpoint          402 + price in USD
agent --sign--> permit (offchain, no gas)
relayer --settle()--> Flare     permit + transferFrom
agent <--200-- endpoint          resource delivered

Why this needs Flare specifically

  • FAssets / FXRP is the settlement asset. FAssets gives XRP a way onto Flare; this gives it a reason to move.
  • FTSO prices every invoice. Invoices are denominated in USD and settled in FXRP at Flare's enshrined onchain feed, so the oracle is load-bearing rather than decorative.
  • EIP-2612, not EIP-3009. FXRP implements permit, not transferWithAuthorization. Every x402 implementation written for USDC assumes the latter, so the signing path here had to be built against Flare's actual token.

Run the probe

Read-only. Needs no keys and spends no gas. It reports every fact the facilitator depends on, and fails loudly if signatures would not verify. 

git clone https://github.com/Ritapossible/Scrip.git
cd Scrip
npm install
npm run probe

Connecting a client

The MCP server that lets Claude Code, Cursor, or VS Code spend through Scrip is not built yet. When it is, it will be documented here.

Known limitation

EIP-2612 nonces are sequential per payer, so an agent paying two endpoints concurrently will have the second permit fail on a consumed nonce. EIP-3009's random nonces avoid this, but FXRP does not implement EIP-3009. Payments are serialised per payer until that is addressed.
